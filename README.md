# 천공월아민간군사기업 관리 패널
Piercing Crescent Moon Private Military Company Management Panel

웹 · Windows(exe) · Android(apk)로 동작하는 관리 패널 앱. 한 벌의 코드(`src/`)를 `www/`로 번들해 세 곳에서 모두 사용합니다.

## 기능
- **인트로**: 검은 화면에서 오른쪽→왼쪽으로 스캔되며 로고가 드러나고 제목·부제가 해독됩니다. 전력 활성화 효과음이 스캔과 동기화됩니다. 다시보기 버튼은 없고, 앱을 나갔다 들어오면(새로 실행) 다시 재생됩니다.
- **로그인 / 회원가입**: 별도 화면. Firebase Authentication(이메일+비밀번호), 계정별 데이터는 Firestore.
- **2차 보안**: 비밀번호 로그인 뒤 6자리 PIN을 접속할 때마다 확인합니다. 복구 코드 8개(1회용)로 PIN 재설정·새 기기 등록이 가능합니다.
- **콜사인 중복 금지**: 같은 이름(대소문자·공백·`_`·`-` 차이는 같은 이름으로 봄)으로는 가입할 수 없습니다. Firestore `nicks/` 문서 + 보안 규칙으로 동시 가입 경쟁도 막습니다.
- **기기 등록**: 처음 쓰는 기기는 이미 등록된 기기에서 확인 코드를 대조해 승인해야 로그인됩니다(최대 5대, 복구 코드로도 등록 가능). 패널 상단의 기기 버튼에서 목록 확인/삭제.
- **동시 접속 1곳**: 다른 곳에서 로그인하면 기존 접속은 10초 안에 종료됩니다(저장 직전에도 확인해 데이터를 덮어쓰지 않음).
- **메인 패널**: CCTV 캠 / 현장 지휘 / 오늘의 보고서 올리기. 사운드 끄기는 이 화면에만 있습니다.
- **CCTV 캠**: 기지 10개 채널(부서 방 8 + 복도 + 정문), 확대 보기.
- **현장 지휘(쯔꾸르 스타일)**: 화면 이동(드래그/WASD/핀치), 캐릭터를 눌러 *방으로 보내기 · 임무 보내기 · 순찰 보내기 · 대화 엿듣기*(혼잣말).
- **커스터마이징**(패널 03 또는 현장 지휘에서 캐릭터 선택 → 커스터마이징):
  - **이름**: 이름과 라틴어 코드네임을 직접 바꿀 수 있습니다(중복 불가, 기본값으로 되돌리기 가능).
  - **머리**: 남성 10 + 여성 10 스타일, 14색 견본 + 직접 색 선택.
  - **무기 13종**: 단검·쇼트소드·롱소드·그레이트소드·창·방패·레이피어·건틀렛·망치·두손 망치·손도끼·**서리 대검**·배틀엑스 (스프라이트에 표시, 각자 능력치 보정).
  - **스탯**: 근력·방어력·기술·카리스마·매력·지혜 각 최대 10. 캐릭터마다 40~50 포인트(랜덤)를 배분합니다.
  - **특성 뽑기**: 캐릭터마다 10회. 일반 70% / 희귀 25% / 전설 5%, 등급별 20개(전설 중에는 불리하기만 한 특성도 있음). 최대 3개 장착.
  - **능력**: 원격 감지·드래곤(장착하면 등에 푸른 뼈대와 노란 막의 날개가 달림)·카피캣·괴력·은신 — 연구로 해금 후 캐릭터당 최대 2개 장착.
- **날씨**: 기본 지형은 눈 덮인 땅(적설 %). 하루 단위로 맑음 35% / 비 20% / 안개 20% / 한파 25%가 정해지고 내일 예보를 볼 수 있습니다. 특수 효과는 **한파 = 이동 속도 -25%**, **안개 = 임무 성공률 -10%p**뿐입니다(방한복·방한 팩 / 안개 고글로 무시 가능). 쌓인 눈은 마당 이동을 최대 20% 늦춥니다. 직원에게 **재설 작업**(2시간, 약 -30%)이나 **용광로 발전**(3시간, 약 -72%, 한 번에 1명)을 시켜 눈을 치우거나 녹일 수 있습니다.
- **상점**(패널 05): 능력치 증표 6 · 장비 10(방어구/장신구) · 소모품 5 · **가구 40종**. 가구는 방마다 4칸에 배치하며, 그 방을 거처로 쓰는 인원 모두에게 효과가 적용됩니다(선호 방이면 ×1.5, 유지비는 가구 1개당 1회). 장비·증표·소모품은 커스터마이징의 “장비” 탭에서 사용합니다.
- **팀장**(패널 06): 부서마다 고정된 팀장 8명(유승호·강태오·석규민·유채원·서하린·장이안·하늘·마덕수). 관리자와 대화하는 유일한 인물로, 보고 듣기 / 격려(하루 1회, 사기 +8) / 지원 요청(2,000 CR, 하루 1회) 대화가 있고 친밀도가 오를수록 같은 부서 팀원의 임무 성공률이 올라갑니다.
- **사건(이벤트) 엔진**: 게임 시간 1시간마다 12% 확률로 사건이 터지고(하루 최대 3건, 하루 종료 90분 전부터는 발생하지 않음) **시간이 멈춘 채** 선택을 기다립니다. 부서 특수 사건 24건(부서마다 3건) + 날씨·적설 조건 사건 3건(한파의 밤·안개·눈이 많이 쌓였을 때)이 있으며, 분위기는 다크 판타지 디스토피아입니다. 선택지는 비용(CR), 능력치 판정(그 부서에서 해당 능력치가 가장 높은 인원이 나서고 성공 확률이 미리 표시됨), 결과(자금·평판·사기·HP·아이템·연구 포인트·팀장 친밀도·적설·**하루짜리 버프**)로 이루어집니다. 같은 사건은 6일 안에 다시 나오지 않고, 결정은 “나중에 결정”으로 접어 둘 수 있으며(화면 아래 *사건 대기* 버튼) 확인하면 이전 속도로 다시 흐릅니다. 오늘 일어난 사건과 결과는 보고서의 “사건 기록”에 남습니다. 스토리 1장은 이 엔진 위에 이후 추가할 예정입니다.
- **단체 임무**(현장 지휘 → 지도 우측 인원 아이콘 또는 인원 목록 맨 위 *단체 임무 출동*): 부서 무관 3~6명이 함께 출동하는 임무 4종(거점 합동 소탕 · 대규모 호송 · 폐허 정밀 수색 · 긴급 구호). 성공률은 참가자 개인 성공률의 평균에 인원 시너지(최소 인원 초과 1명당 +2%, 최대 +6%)와 합동 보너스(2개 부서 이상 +2%)를 더한 값이며, **한 번의 판정으로 전원이 같은 결과**를 받습니다(실패하면 전원 부상). 전원이 임무 지역에 도착해야 시간이 흐르고, 인원이 많을수록 총 보상이 늘어납니다. 보고서에는 단체 임무 1건으로 기록됩니다.
- **부서 재집결**(현장 지휘 → 인원 목록): 부서 머리글마다 *재집결* 버튼이 있어 그 부서 인원 전원을 부서 방으로 불러 모읍니다(순찰·작업은 중단, 임무 중인 인원과 부상자는 제외).
- **연구**(패널 04): 연구 포인트는 보고서를 올릴 때마다 +1. 능력 10pt, 3배속 해금 5pt, 수입 +0.5%(20단계, 단계마다 비용 +2), 특성 재도전 +1회, 의무 강화.
- **백그라운드 유지**: 앱을 가려도(탭 전환·최소화·다른 앱) 게임 시간이 계속 흐릅니다. 돌아오면 벗어난 시간만큼 따라잡고 요약 알림을 보여 줍니다(정지 상태였다면 멈춘 채 유지). Android 는 OS 가 앱을 멈춰도 복귀 시 따라잡으며, 로그인은 유지하고 인트로만 다시 재생합니다(10분 넘게 비우면 2차 보안 재확인).
- **시간**: 하루 = 아침 12시간 + 밤 9시간(게임 내 06:00→03:00), 1배속 실제 12분. 정지 / 재생 / 2배속 / 3배속(연구 해금). 보고서를 올리면 하루가 끝나고 다음 날이 시작됩니다.
- **8개 부서 · 25명**: Operation, Rager, Defencer, Requester, Medical, Raider, Aerial Striker, Carrier. 각 인원에 라틴어 코드네임이 있습니다.

## 1. Firebase 설정 (필수 — 다른 사람도 다른 계정으로 로그인하려면)
1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트 생성 → **웹 앱 추가** → `firebaseConfig` 복사.
2. **Authentication → 로그인 방법 → 이메일/비밀번호** 사용 설정.
3. **Firestore Database** 생성(프로덕션 모드) 후 이 저장소의 `firestore.rules` 내용을 규칙에 붙여넣고 게시 (**콜사인 중복 방지용 `nicks` 규칙 포함 — 반드시 게시**) (`firebase deploy --only firestore:rules` 도 가능).
4. `src/config/firebase-config.js` 의 `placeholder` 값을 복사한 값으로 교체하고 커밋. 또는 GitHub 저장소 *Settings → Secrets → Actions* 에 `FIREBASE_CONFIG_JSON`(firebaseConfig 를 JSON 한 줄로)을 등록하면 CI 빌드에 주입됩니다.
5. API 키에 **HTTP 리퍼러 제한을 걸었다면** exe(`file://`)·apk(`https://localhost`)에서 막힐 수 있으니 제한 없이 두거나 Firebase 콘솔에서 허용 도메인을 확인하세요.

설정값이 비어 있으면 앱은 **로컬 시험 모드**로 동작하며 로그인 화면에 `LOCAL TEST`가 표시됩니다(계정이 그 기기 안에만 존재).

## 2. 2차 보안에 대한 정직한 설명
2차 보안은 **6자리 PIN 하나**입니다(인증 앱은 제거됨). 검증이 앱(클라이언트) 안에서 이뤄지고 PIN 해시가 본인의 Firestore 문서에 저장되므로, **비밀번호를 알고 Firestore 를 직접 읽을 수 있는 공격자**는 우회하거나 6자리 숫자를 오프라인으로 대입할 수 있습니다. 자리를 비운 사이의 접근 같은 가벼운 위협용이며, 강한 보안이 필요하면 Firebase Identity Platform 공식 MFA 로 전환하세요.
- 기기 등록·동시 접속 제한도 같은 한계가 있습니다(앱 안에서 검사).
- PIN 을 잊었을 때: 복구 코드로 재설정. 복구 코드까지 잃으면 Firebase 콘솔에서 `users/{uid}` 문서의 `mfa` 필드를 삭제하면 다음 로그인 때 재설정됩니다.
- 5회 연속 실패 시 30초부터 잠금(장치 단위).

## 3. 개발 / 빌드
```bash
npm install
npm run test:unit      # 코어 로직 테스트(해시, 콜사인, 맵, 시뮬레이션)
npm run build:web      # www/ 생성
npm run dev            # http://localhost:5173 (watch + 서버)
npm run electron:dev   # 데스크톱 창으로 실행
npm run dist:win       # Windows exe(설치형 + 포터블) → dist/   (Windows 에서 실행 권장)
npm run cap:android    # android/ 생성·동기화, 이후 android/ 에서 ./gradlew assembleDebug
```
**자동 빌드**: `main` 에 푸시하면 GitHub Actions(`.github/workflows/build.yml`)가 exe 와 apk 를 만들어 **Releases** 에 올립니다. 수동 실행은 Actions 탭 → *Build exe + apk* → Run workflow.
apk 는 디버그 서명이라 바로 설치되지만 Play 스토어 배포용이 아닙니다(배포하려면 릴리스 키로 서명하세요).

### apk 업데이트 시 “패키지가 기존 패키지와 충돌합니다” 오류
원인은 **서명 키가 빌드마다 달라서**입니다. CI 서버는 빌드할 때마다 새 디버그 키를 만들기 때문에, 이미 설치한 앱 위에 새 apk 를 설치하면 Android 가 거부합니다. 이제 `android-signing/pcm.jks` 로 **항상 같은 키로 서명**하고 `versionCode` 는 시간 기준으로 계속 늘어납니다(`scripts/android-prepare.mjs`).
- **이 수정 이전에 설치한 앱은 한 번만 삭제 후 새로 설치**해야 합니다. (이후 업데이트는 덮어쓰기로 됩니다. Firebase 로 로그인했다면 게임 데이터는 서버에 있어 유지되고, “로컬 시험 모드”였다면 기기 안의 데이터는 삭제됩니다.)
- 키 파일과 비밀번호는 저장소에 들어 있는 **개인 사이드로딩용 키**입니다. 저장소가 공개라면 누구나 같은 키로 서명할 수 있으니, 공개 배포를 한다면 새 키를 만들어 GitHub Secret 으로 옮기세요(그때는 한 번 더 삭제 후 재설치가 필요합니다).

## 4. 디자인 메모
- 방향: *냉전기 홀로그램 터미널* — 검정 + 얼음빛 은백색, 신호 색은 호박(amber) 하나. 폰트는 Noto Sans KR + IBM Plex Mono 두 가지.
- 홀로그램 그리드/스캔라인: 선(1px)만 사용, 64px 간격(면적 약 3%), 스캔 9초 주기. 촘촘한 구멍 패턴(트립포비아)·초당 3회 초과 점멸(광과민)을 피했고 `prefers-reduced-motion` 을 존중합니다.
- 성능: FPS 가 40 미만으로 2초 지속되면 장식 효과를 자동 단계 하향(최저 30fps 유지가 목표).
